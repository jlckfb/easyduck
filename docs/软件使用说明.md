# 软件使用说明

## 运行结构

```text
网页（9527）/ 手柄 padd → robotd → HD1910 舵机（/dev/ttyS3）
                              → LSM6DSV16X IMU（/dev/i2c-2）
                              → ONNX 动作模型、音效
标定台（8766）→ 独占舵机串口与 IMU
```

`robotd` 负责主控制，`padd` 读取手柄，`robotctl` 提供状态查询和命令行操作，`sounds` 生成音效。网页和标定台是 Python 服务。

## 系统与依赖

- 主板：泰山派 1M，Linux ARM64；舵机：HD1910；IMU：LSM6DSV16X。
- 板端需要 UART3 GPIO116 半双工支持、Python 3.9+、ONNX Runtime 1.23 或以上、ALSA 工具 `aplay`/`amixer` 以及 systemd。串口补丁见 `deploy/kernel/`。
- 蓝牙手柄需要系统 BlueZ、`bluetooth.service` 和输入设备权限；`padd` 直接读取输入事件。
- 编译需要 Linux、Docker、Rust、ARM64 交叉编译器和 ARM64 系统库。版本与库清单见 `deploy/dependencies.lock.json`，Rust 包版本见 `runtime/Cargo.lock`。

## 编译

在 Linux x86-64 编译机的仓库根目录运行，先使用 Dockerfile 创建环境：

```sh
docker build -f deploy/Dockerfile -t easyduck-build:1.98.1 .
docker run -d --name easyduck-build --network none easyduck-build:1.98.1
bash deploy/build.sh
```

创建镜像需要联网下载系统包、固定版本 Rust 和 Cargo 依赖；无需已有编译容器、sysroot 或个人 Cargo 缓存。应用构建使用 `--locked --offline`，编译容器可保持无网络。容器已存在时使用 `docker start easyduck-build`，依赖更新后重建镜像并换用新容器。完整环境说明见[编译与部署](../deploy/README.md)。

输出为 `build/bin/` 中的 `robotd`、`padd`、`robotctl`、`sounds`；构建日志输出到 `build/logs/`。

## 单元测试与文件校验

```sh
(cd runtime && cargo test --locked --workspace)
```

以上命令在具备 Rust 和本机 libudev 开发库的 Linux 环境运行，不执行交叉编译出的 ARM64 程序。源码内单元测试使用模拟输入，不要求连接机器人；独立本地测试脚本不是使用本软件的前提。模型文件完整性可使用随模型提供的校验清单检查：

```sh
(cd models && sha256sum -c SHA256SUMS)
```

## 配置

从 `config/examples/` 开始配置。样例默认关闭动作策略，零点 2048 仅表示文件格式，不代表实物中位。`config/board/` 是特定机器的参考配置，不可直接用于其他机器人。

主要文件：

| 文件 | 用途 |
| --- | --- |
| robotd.toml | 串口、控制频率、IMU、动作模型、音效 |
| visual_calibration.json | 各舵机零点、方向、限位及 IMU 安装与偏置 |
| zero_pos.json | 舵机基线零点、方向与限位 |
| scs_joint_gains.json | 分关节 P 增益覆盖 |
| voice.env | 音效生成种子 |

运行时配置目录为 `/etc/robot/`。主控启动时读取配置，修改后需重启服务。舵机驱动优先读取 `visual_calibration.json`。文件缺失时，使用驱动内置零点和方向，并从 `zero_pos.json` 读取限位；该文件的零点和方向必须与内置基线一致，否则启动报错。新机器应通过标定台生成匹配的 `visual_calibration.json`。配置详情见[配置说明](../config/README.md)。

## 暂存安装与回退

先安装到测试目录，不启动服务：

```sh
python3 deploy/install.py --root build/stage --profile examples
# BACKUP_DIR 替换为安装器返回的备份目录
python3 deploy/install.py --root build/stage --verify BACKUP_DIR/manifest.json
python3 deploy/rollback.py --root build/stage --backup BACKUP_DIR
```

安装内容包含 `/opt/robot/licenses/THIRD_PARTY_NOTICES.md`，与应用文件一起校验和回退。

安装器默认保留已有配置。只有 `--replace-config` 才覆盖配置并备份。回退只处理安装清单中的文件，不自动启动服务。

## 板端安装与启动

安装前停止控制及标定服务，承托机器人并确认断力；准备与该机器匹配的配置。

```sh
python3 deploy/install.py --root / --profile examples --install-on-board
bash deploy/start.sh
# 确认预览后启动服务
bash deploy/start.sh --execute
```

`examples` 配置需完成实物标定后才能用于动作。`--profile board` 只适用于匹配参考配置的同一台机器。

- 正式网页：`http://开发板IP:9527`。
- 标定台：`http://开发板IP:8766`。启动 `xgoduck-calibration.service` 会停止正式控制服务，避免同时占用串口。
- 查询服务：`systemctl status robotd padd xgoduck-web`。
- 查看日志：`journalctl -u robotd -f`。

音效由 `sounds` 在服务启动前按 `voice.env` 生成到 `/var/lib/robot/sounds/`，已有匹配版本的音效库可直接复用。

## 板端回退

停止控制及标定服务后，选择安装器生成的备份目录：

```sh
python3 deploy/rollback.py --root / --backup BACKUP_DIR --restore-on-board
systemctl daemon-reload
```

回退不会自动启动服务或上力。再次运行前核对配置、模型和程序版本是否匹配。

## 日常操作

- 使用网页前确认 `robotd` 和 `xgoduck-web` 已启动；页面中的上力和动作按钮会控制实物。
- 使用手柄前完成系统蓝牙配对，并启动 `padd`；网页与手柄的控制权由主控协调。
- 只读查看可用 `robotctl robot mode --json` 或 `robotctl monitor`。命令、参数编辑与控制操作见[命令行工具说明](../runtime/robotctl/README.md)。
- 需要标定时执行 `systemctl start xgoduck-calibration.service`，正式控制服务会停止。结束后执行 `systemctl stop xgoduck-calibration.service`，再按启动步骤恢复正式服务。
- 终止控制服务不等于舵机已经断力；操作或移动实物前核对断力状态。

## 实物检查

按串口反馈、舵机方向与限位、IMU 方向、承托下的上力、站立及各动作逐项检查。编译、模拟测试和模型结构检查不能证明实物动作正确。

### 手柄前后速度

行走模式下，左摇杆推满前进时，前100毫秒目标速度为0.25 m/s，随后保持0.15 m/s；推满后退时，前100毫秒为−0.30 m/s，随后保持−0.25 m/s。摇杆未推满时按持续速度同比例输出，回中立即发送零前后速度。

满杆按95%行程判定；回收到90%或更少后允许再次触发，避免顶端抖动反复触发。换方向、切换头部／身体模式、手柄断开会清除计时。向左满杆最大指令为0.55 m/s，向右仍为0.30 m/s。以上均为发给策略的目标速度，实际行走速度以实物测量为准。

`padd --max-linear` 调整持续前进速度，`--max-linear-backward` 调整持续后退速度，`--max-lateral-left` 调整左移速度，`--max-lateral` 调整右移速度。起步倍率分别为5/3和1.2，持续100毫秒。网页控制和轮式模式使用各自的速度设置。
